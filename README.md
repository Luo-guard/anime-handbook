# 动漫手账

一个读取 Kazumi 本地收藏的轻量 Windows 动漫进度与观后感手账。

## 统一项目目录

- `app.py`、`static/`、`tests/`：电脑版服务、界面和测试。
- `server/`：独立线上入口、账号登录和请求隔离；与电脑版共用业务逻辑和页面。
- `deploy/online/`：线上启动、HTTPS、后台常驻、迁移与备份说明。详见 [线上版说明](deploy/online/README.md)。
- `android/`：安卓版唯一源码目录；共用手账数据格式，通过坚果云与电脑同步。
- `releases/android/`：可安装的 Android APK。
- `tools/`：启动、同步、安卓打包和跨端排序验证工具。
- `data/`：电脑本地数据库、账号、图片、配置及备份，不能当作构建缓存删除。
- `shared/`：当前 Syncthing 共享目录；`共享/` 是保留的旧共享资料。
- `archive/`：旧图片布局测试版源码归档及整理记录。

线上版使用独立数据目录和端口，不会启动本机 Kazumi／坚果云同步。现有电脑版启动脚本和安卓版保持原用法；APK 的线上账号接入将在网站部署后进行。

双击 `打包安卓版.cmd`，先运行安卓单元测试，再生成 APK 到 `releases/android/`。
打包工具会将 `android/` 中的源码复制到临时英文路径，绕过中文路径下的安卓测试问题；结束后自动清理临时目录。首次缺少依赖时运行 `powershell -ExecutionPolicy Bypass -File tools/build_android.ps1 -Online`。本机使用 Java 17、Gradle 8.9 和 `D:\Program Files (x86)\AndroidSdk`，路径可在脚本参数与 `android/local.properties` 中配置。

跨端排序检查：`node tools/verify_mobile.cjs`。不传参数时使用测试样例，也可以传入包含 `anime` 数组的 JSON 文件。

## 启动

双击 `启动动漫手账.cmd`。也可在项目目录运行：

```powershell
python app.py
```

浏览器会自动打开 `http://127.0.0.1:43127`。

## 数据安全

- 收藏支持独立搜索添加和状态编辑；没有 Kazumi 收藏时可用“批量导入”按名单逐条搜索并加入；启用自动写回时，待同步任务会在 Kazumi 关闭后写入 `collectibles.hive`，写前备份、写后读回验证。设置中的“只读 Kazumi 数据”可一次性关闭这些编辑入口并暂停写回。详见 [Kazumi 写回说明](docs/kazumi-writeback.md)。
- 手账自己的收藏快照、集数、进度、时间线与设置都保存在 `data/handbook.db`。
- 封面缓存保存在 `data/covers/`。
- Kazumi 运行时会独占数据库；关闭 Kazumi 后点击“同步收藏”即可导入，之后打开手账也会自动同步。

## 坚果云多端同步

在“设置 → 共享与账号 → 坚果云多端同步”中填写：

1. WebDAV 地址：`https://dav.jianguoyun.com/dav/`
2. 坚果云账号，以及坚果云生成的**应用密码**（不要填写网页登录密码）。
3. 首台设备保留自动生成的“云端账号标识”，保存后点击“立即同步当前账号”。
4. 在另一台设备新建或打开对应的本机手账账号，填入相同的坚果云配置和云端账号标识；首次同步会下载云端数据。

同步只上传手账账号数据（收藏状态、进度、记录、设置、排名等），不会上传 Kazumi 数据库、封面、角色资料和 AGE 缓存；这些可从动漫 ID 重新获取。密码只保存在填写它的本机。

如果电脑和手机都在上次同步后新增过记录，同步会自动合并两边的观看记录、感想和评论。相同番剧的同一集只保留一条观看记录，以较早的观看时间为准（按实际时区比较）；不同番剧、不同集数的新增记录都会保留，重复同步不会重复计数。旧版一次记录多集的观看记录会按集拆分合并。

这里的增量是新增记录的合并；当前 WebDAV 仍传输账号 JSON 快照，有改动时上传，无改动时优先用 ETag 轻量检查。并发合并保留本机的设置和排行榜；删除或修改既有感想并不是带删除标记的双向合并协议。

## 放送周表

侧边栏“周表”可选择 2015 年以来的季度，按周一至周日查看番剧，网络放送与其他独立上线作品单独展示。卡片沿用手账竖版封面形式，显示放送时间、收藏状态、评分和评分人数；点击可查看简介、播放平台链接，已收藏作品可进入进度记录。

- “排序与筛选”支持时间顺序、评分优先和热度优先；热度采用评分人数。
- 季度接口未收录的作品，会通过 Bangumi 当前放送资料补充；跨季续播作品通过上一季度的标题对应关系补充元数据，不会把上一季度的整份清单混入当前周表。来源页面没有首播日期时，使用已关联 Bangumi 条目的首播日期；“全26话”等集数说明不当作日期。
- 标题关联统一识别“第2期／第二季／Season 2／Ⅱ”等季数写法，并保留不同季数、篇章的区别。所有接口仍未覆盖的作品会按来源原名、完整译名自动查询 Bangumi，再经过唯一性校验关联；没有按番名维护特殊规则。
- 自动查询的候选资料保存在 `data/schedule/lookups/`：成功结果缓存 6 小时，空结果缓存 1 小时；下次周表更新会重新尝试。请求并发限制为 2，连续失败会停止本轮补全。资料缺失与已确认零人评分分别显示，无法可靠关联时保留待匹配状态。
- 五种收藏状态可以组合筛选；“显示未收藏的番剧”可独立开关。也可以在“设置 → 周表”配置，偏好随账号保存。
- “设置 → 周表”位于收藏夹设置下方，可分别开关卡片标签／集数说明、评分人数、右下角首播日期／平台、右上角评分、左上角收藏状态及封面放送时间。只控制卡片显示，不影响资料获取、排序、筛选或详情内容。
- 播出日固定按北京时间凌晨 4 点划分；例如周一来源时间 `25:30` 显示为“次日 01:30”，仍归周一。时间按来源标注，不保证等同于字幕更新或所有平台的上线时间。
- 时间、上线日期与平台信息来自 [長門番堂](https://yuc.wiki/)，保留 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/deed.zh) 来源标注；评分资料来自 Bangumi，经 Kazumi 季度接口获取。未公布的时间不推算，无法可靠关联的条目不强行匹配。
- 元数据与封面缓存在 `data/schedule/`，不写入收藏数据库，也不上传到坚果云。缓存 6 小时后后台刷新，来源故障时保留已有缓存；手动刷新有 60 秒请求间隔。
- 季度和星期切换后只渲染当前清单，首批最多 30 张卡片（其余可继续展开），封面懒加载；离开周表会取消请求和轮询。

## 测试命令

周表前端回归：`node tests/verify_schedule.cjs`。后端测试包含解析、跨日边界、缓存、图片、匹配与设置接口验证。

看番记录按约 30 条分批加载，分页会保留最后一天的完整记录；继续向下滚动自动加载，也可点击“加载更多记录”。搜索和主题筛选在服务端分页前执行。离开记录页面会取消请求并释放已渲染的记录卡片。浏览完整历史时，已经加载的记录仍会保留，方便向上回看。

前端分页回归检查：`node tests/verify_timeline.cjs`。

```powershell
python -m unittest discover -s tests -v
```
