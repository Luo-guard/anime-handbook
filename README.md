# 动漫手账

一个围绕 Kazumi 本地收藏的动漫进度与观后感手账：放送周表、看番记录与时间线、可自定义的番剧详情跳转链接，以及基于蜜柑计划 + qBittorrent 的离线下载与浏览器内播放。提供 Windows 桌面版（本地服务 + 浏览器界面）、线上版与安卓版，多端通过坚果云同步。

功能演进见 [CHANGELOG.md](CHANGELOG.md)，离线下载的完整设计与边界见 [docs/OFFLINE-PLAN.md](docs/OFFLINE-PLAN.md)。

## 统一项目目录

- `app.py`、`static/`、`tests/`：电脑版服务、界面和测试。
- `server/`：独立线上入口、账号登录和请求隔离；与电脑版共用业务逻辑和页面。
- `deploy/online/`：线上启动、HTTPS、后台常驻、迁移与备份说明。详见 [线上版说明](deploy/online/README.md)。
- `android/`：安卓版唯一源码目录；共用手账数据格式，通过坚果云与电脑同步。
- `releases/android/`：可安装的 Android APK。
- `tools/`：启动、同步、安卓打包和跨端排序验证工具。
- `data/`：电脑本地数据库、账号、图片、配置及备份，不能当作构建缓存删除。
- `shared/`：当前 Syncthing 共享目录；`共享/` 是保留的旧共享资料。
- `archive/`：旧图片布局测试版源码归档及整理记录。
- `handbook/`：后端业务逻辑，含收藏、周表、跳转链接规则与离线下载（蜜柑／qBittorrent／媒体处理／字幕）等模块，见 [handbook/README.md](handbook/README.md)。
- `static/modules/`：前端模块，见 [static/modules/README.md](static/modules/README.md)。
- `docs/`：专题文档（离线方案、Kazumi 写回、交接与加固记录等）。
- `static/vendor/jassub/`：页面内字幕所用的 libass wasm 版与开源中文字体，本地打包、不依赖 CDN；新安装运行 `node tools/prepare_subtitles.cjs` 生成，详见 [字幕资源准备说明](tools/subtitles/README.md)。

线上版使用独立数据目录和端口，不会启动本机 Kazumi／坚果云同步。现有电脑版启动脚本和安卓版保持原用法；APK 的线上账号接入将在网站部署后进行。

双击 `打包安卓版.cmd`，先运行安卓单元测试，再生成 APK 到 `releases/android/`。
打包工具会将 `android/` 中的源码复制到临时英文路径，绕过中文路径下的安卓测试问题；结束后自动清理临时目录。首次缺少依赖时运行 `powershell -ExecutionPolicy Bypass -File tools/build_android.ps1 -Online`。本机使用 Java 17、Gradle 8.9 和 `D:\Program Files (x86)\AndroidSdk`，路径可在脚本参数与 `android/local.properties` 中配置。

跨端排序检查：`node tools/verify_mobile.cjs`。不传参数时使用测试样例，也可以传入包含 `anime` 数组的 JSON 文件。

## 启动

双击 `启动动漫手账.cmd`。也可在项目目录运行：

```powershell
python app.py
```

浏览器会自动打开 `http://127.0.0.1:43127`。

后端以 Python 标准库为主（Python 3.10+，开发用 3.12），`requirements.txt` 只有可选的 `pillow-heif`（HEIF 封面）。离线下载与页面内播放是可选功能，需要本机另外准备 qBittorrent 和 ffmpeg，见下一节。

## 数据安全

- 收藏支持独立搜索添加和状态编辑；没有 Kazumi 收藏时可在“搜索添加番剧”里点“批量搜索”，按名单逐条搜索并加入；启用自动写回时，待同步任务会在 Kazumi 关闭后写入 `collectibles.hive`，写前备份、写后读回验证。设置中的“只读 Kazumi 数据”可一次性关闭这些编辑入口并暂停写回。详见 [Kazumi 写回说明](docs/kazumi-writeback.md)。
- 手账自己的收藏快照、集数、进度、时间线与设置都保存在 `data/handbook.db`。
- 封面缓存保存在 `data/covers/`。
- Kazumi 运行时会独占数据库；关闭 Kazumi 后点击“同步收藏”即可导入，之后打开手账也会自动同步。

## 离线下载与本地播放

在番剧详情页点「找资源」，输入关键词搜索 [蜜柑计划](https://mikanani.kas.pub/) 的 RSS，挑一条种子交给本机 qBittorrent；下载完成后自动整理入库，然后可以直接在页面里播放。番名不做自动匹配，搜什么、选哪一条完全由你决定。

- **准备（一次性）**：qBittorrent 开启「Web UI」，监听 `127.0.0.1:8080`，勾选「对本地主机客户端免除认证」并关闭 CSRF 保护；本机安装 ffmpeg（用于无损换壳与字幕抽取）；浏览器建议 Edge / Chrome（HEVC 播放需要系统解码支持）。这些是本机配置，存在数据目录的 `offline.json`，不随账号同步。
- **下载**：搜索结果按字幕组、分辨率、编码、位深、字幕类型、大小、时间、是否为合集拆分显示，可按字幕组筛选。手账自己取回 `.torrent` 校验后再提交给下载器，避免下载器直连受阻。支持进度条、速度与剩余时间、暂停／继续，以及失败任务的自动限频重试与手动「重试归档」。
- **归档**：用 `ffmpeg -c copy` 只把容器换成 mp4（HEVC 打 `hvc1` 标记），**不转码、不损失画质**，同时抽出内封 ASS 字幕，按 `<番名>/第 01 集.mp4` 归档。播放走原生 `<video>` + HTTP Range，进度条可拖动，播放进度会记住。
- **字幕**：由 libass 的 wasm 版（jassub）在页面内渲染，ASS 特效与定位保留；优先使用 MKV 内封的字体附件，缺失时回退到打包的 Noto Sans SC。播放器带「字幕 · 开/关」。播放器保持原生 `<video>`，所以 NijiLucid 这类抓帧超分扩展仍可接管。
- **自动追番**：在搜索结果上点「订阅」记住「关键词 + 字幕组」，之后只下这个字幕组的新集。默认关闭；首次检查只记基准不下载，一次只下最新一条，同一条种子不重复下。
- **媒体库**：目录可在离线面板「设置」里改，并支持把已有文件迁移过去（逐个复制并校验大小，全部成功才切换目录，默认保留源文件），也会显示磁盘剩余空间。**务必把媒体库放在项目目录之外**——同步工具会推送项目内文件，几十 GB 的视频一旦进项目就可能误传，且历史记录难以清除。
- 蜜柑域名按 `mikanime.tv` → `mikanani.kas.pub` → `mikanani.me` 自动回退，也可在设置里手动指定。新电脑或从 GitHub 部署时，先安装 Node.js 18+（含 npm），在项目根目录运行 `node tools/prepare_subtitles.cjs`，按锁定版本生成全部字幕脚本、WASM、字体和许可声明；之后播放无需 Node 和 CDN。离线转移可复制完整的 `static/vendor/jassub/`，部署打包会校验并包含这些资源，缺失或损坏时拒绝打包。详见 [字幕资源准备说明](tools/subtitles/README.md)。

> 请遵守所在地区的法律法规，仅下载你有权获取的内容；BT 下载会做种并上传数据。

## 坚果云多端同步

在“设置 → 共享与账号 → 坚果云多端同步”中填写：

1. WebDAV 地址：`https://dav.jianguoyun.com/dav/`
2. 坚果云账号，以及坚果云生成的**应用密码**（不要填写网页登录密码）。
3. 首台设备保留自动生成的“云端账号标识”，保存后点击“立即同步当前账号”。
4. 在另一台设备新建或打开对应的本机手账账号，填入相同的坚果云配置和云端账号标识；首次同步会下载云端数据。

同步只上传手账账号数据（收藏状态、进度、记录、设置、排名等），不会上传 Kazumi 数据库、封面、角色资料和 AGE 缓存；这些可从动漫 ID 重新获取。密码只保存在填写它的本机。

如果电脑和手机都在上次同步后新增过记录，同步会自动合并两边的观看记录、感想和评论。相同番剧的同一集只保留一条观看记录，以较早的观看时间为准（按实际时区比较）；不同番剧、不同集数的新增记录都会保留，重复同步不会重复计数。旧版一次记录多集的观看记录会按集拆分合并。

这里的增量是新增记录的合并；当前 WebDAV 仍传输账号 JSON 快照，有改动时上传，无改动时优先用 ETag 轻量检查。并发合并保留本机的设置和排行榜；删除或修改既有感想并不是带删除标记的双向合并协议。

## 放送周表

侧边栏“周表”可选择 2015 年以来的季度，按周一至周日查看番剧，网络放送与其他独立上线作品单独展示。卡片沿用手账竖版封面形式，显示放送时间、收藏状态、评分和评分人数；点击可查看简介、播放平台链接，已收藏作品可进入进度记录。

- “排序与筛选”支持时间顺序、评分优先和热度优先；热度采用评分人数。
- 季度接口未收录的作品，会通过 Bangumi 当前放送资料补充；跨季续播作品通过上一季度的标题对应关系补充元数据，不会把上一季度的整份清单混入当前周表。来源页面没有首播日期时，使用已关联 Bangumi 条目的首播日期；“全26话”等集数说明不当作日期。
- 标题关联统一识别“第2期／第二季／Season 2／Ⅱ”等季数写法，并保留不同季数、篇章的区别。所有接口仍未覆盖的作品会按来源原名、完整译名自动查询 Bangumi，再经过唯一性校验关联；没有按番名维护特殊规则。
- 自动查询的候选资料保存在 `data/schedule/lookups/`：成功结果缓存 6 小时，空结果缓存 1 小时；下次周表更新会重新尝试。请求并发限制为 2，连续失败会停止本轮补全。资料缺失与已确认零人评分分别显示，无法可靠关联时保留待匹配状态。
- 五种收藏状态可以组合筛选；“显示未收藏的番剧”可独立开关。也可以在“设置 → 周表”配置，偏好随账号保存。
- “设置 → 周表”位于收藏夹设置下方，可分别开关卡片标签／集数说明、评分人数、右下角首播日期／平台、右上角评分、左上角收藏状态及封面放送时间。只控制卡片显示，不影响资料获取、排序、筛选或详情内容。
- 播出日固定按北京时间凌晨 4 点划分；例如周一来源时间 `25:30` 显示为“次日 01:30”，仍归周一。时间按来源标注，不保证等同于字幕更新或所有平台的上线时间。
- 时间、上线日期与平台信息来自 [長門番堂](https://yuc.wiki/)，保留 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/deed.zh) 来源标注；评分资料来自 Bangumi，经 Kazumi 季度接口获取。未公布的时间不推算，无法可靠关联的条目不强行匹配。
- 元数据与封面缓存在 `data/schedule/`，不写入收藏数据库，也不上传到坚果云。缓存 6 小时后后台刷新，来源故障时保留已有缓存；手动刷新有 60 秒请求间隔。
- 季度和星期切换后只渲染当前清单，首批最多 30 张卡片（其余可继续展开），封面懒加载；离开周表会取消请求和轮询。

## 番剧详情与单集操作

- 详情页那一行跳转链接可以在设置里改名、改顺序、启用或隐藏；「更多站点」是一条总链接，点击后弹出站点选择窗，可搜索，也可把常用站点图钉固定回详情页。站点清单来自 [KazumiRules](https://github.com/Predidit/KazumiRules) 规则仓库，可在设置里手动检查更新（不自动更新）。
- 看番记录支持「默认展示记录类型」多选；批量导入支持 `.xlsx`（浏览器内解析，无需额外依赖）。
- 集数格子的左键单击固定用于记录已看，不参与改绑。长按或右键弹出六格扇区（播放／下载／评分／评价／OP／ED）：滑过去松手即执行，或原地松手后再点选。每格放什么动作、是否显示，以及右键／长按／修饰键组合／双击／中键分别触发什么，都能在「设置 → 快捷键 → 单集格子手势」里改。绑定双击会让单击增加约 0.25 秒判定延迟，设置里会明确提示。

## 测试命令

周表前端回归：`node tests/verify_schedule.cjs`。后端测试包含解析、跨日边界、缓存、图片、匹配与设置接口验证。

看番记录按约 30 条分批加载，分页会保留最后一天的完整记录；继续向下滚动自动加载，也可点击“加载更多记录”。搜索和主题筛选在服务端分页前执行。离开记录页面会取消请求并释放已渲染的记录卡片。浏览完整历史时，已经加载的记录仍会保留，方便向上回看。

前端分页回归检查：`node tests/verify_timeline.cjs`。

```powershell
python -m unittest discover -s tests -v
```

前端界面回归是 `tests/verify_*.cjs`（需要 Node.js 与 Playwright，全部为 headless 脚本）：

```bash
for f in tests/verify_*.cjs; do node "$f"; done
```

当前基线：后端 478 项、前端 51 个脚本。`test_hardening` 中有一个已知的并发写只读缺陷（`attempt to write a readonly database`）尚未修复，其余全部通过。
