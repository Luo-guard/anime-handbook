# 2026-11-04 接手审查修复

## 修复范围

1. Kazumi 云推送：旧 `kazumi_sync` 可能只是一次观察结果，不能证明本机合并过云端，故不作为可信基线。新基线仅由两端字节一致或成功条件上传建立；冲突不推进基线。已有文件须提供强 ETag，上传使用 If-Match；创建使用 If-None-Match。多个 Hive 文件不是服务器事务，若中途失败保留实际成功部分的基线并提示未完成，不尝试覆盖或回滚他人写入。仍不替代 Kazumi 的双向合并。
2. 记录图片清理：以只读 SQLite 连接汇总账号注册表中全部数据库的引用，避免用当前账号判断共享目录；任何一个数据库读取失败即跳过共享资产清理。
3. 主题背景清理：使用各账号自己的主题设置取并集，保留旧版背景命名；未知引用时停止清理。
4. 笔记：移除自动按正文长度/包含关系删除历史记录的行为。events.record_uid 独立于 SQLite 行号，新增由触发器生成，编辑保持不变，导入导出保留。已有库在添加字段前用 SQLite backup 备份到数据目录 backups；历史行分别分配身份，不猜测哪条是旧版本。云合并同身份按 updated_at 选择；缺少身份的旧客户端只匹配完整内容相同的记录，不推断不同正文属于同一条，故旧版本同步时可能保留额外历史行，优先避免丢失内容。
5. 集号：保留 1、3 等缺口与顺序，续作 49..60 按季度偏移归一；编号缺失仍使用列表位置回退。
6. 刷新：GET /api/airing 返回当前账号的 id/airing，每分钟及页面恢复前台时拉取。无变化不重绘，不重置未提交的观看选择；账号/收藏数组更换使旧请求失效，离线保留缓存。
7. 浏览器迁移：先复制至 .migration-staging，失败继续旧目录并可重试；完成标记仅在复制成功后发布。清理旧目录前校验固定旧路径、禁止目录链接，并核对监听调试端口的进程命令行中的 user-data-dir。

生效需重启桌面后台并刷新网页；迁移自动先备份。其他设备旧客户端若不保存 record_uid，仍采用保守兼容规则。此修复不新增记录编辑时间选择功能。
