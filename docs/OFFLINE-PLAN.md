# 离线下载方案（定稿 2026-11-06）

把番剧下载到本机并管理，目标对齐弹弹play 的「下载 → 媒体库 → 播放」，但片源走蜜柑计划。

本文是施工依据。所有决策都在对话里确认过，并附上了实测证据；改动需求请先改这里。

---

## 0. 一页总览

```
蜜柑搜索 ──→ 结果列表 ──→ 用户选种 ──→ .torrent 到手
                                          │
                                          ↓
                                    交给 qBittorrent
                                          │
                                          ↓
                        轮询进度 ──→ 下载完成 ──→ 探测编码
                                          │
                                          ↓
                                  remux 换壳 + 抽字幕
                                          │
                                          ↓
                              归档为「第 01 集.mp4」入库
                                          │
                                          ↓
                            网页播放（libass 字幕 + 扩展超分）
```

---

## 1. 技术选型与依据

| 决策 | 结论 | 依据 |
|---|---|---|
| 片源 | 蜜柑计划搜索 RSS | `/RSS/Search?searchstr=` 返回标准 XML，字段齐全，实测 2 秒内返回 |
| 域名 | `mikanime.tv` → `mikanani.kas.pub` → `mikanani.me` 顺序回退 | 实测：主域直连和走代理都超时（TCP 都连不上），两个镜像 0.6 秒连上 |
| 下载引擎 | 调用已装的 qBittorrent，不自建 BT | qB v5.1.0 WebUI 已通，免认证可用 |
| 种子上传方式 | 手账自己下载 .torrent，再传给 qB | qB 自己去拉 URL 可能被代理/墙挡住；手账这边已验证能连通 |
| 容器转换 | 只 remux（`-c copy`），不转码 | 实测 3 秒视频 remux 耗时 0.169 秒，体积不变 |
| HEVC 播放 | 直接播 | 实测 Edge 156 + HEVC 扩展 2.5 + RTX 3050 Ti 硬解，HEVC Main10 实播成功 |
| 网页播放器 | 原生 `<video>` + mp4 | 超分扩展只认原生 video，canvas 自绘或 MSE 会失效 |
| 字幕 | libass（jassub） | 与弹弹play/Kazumi 同源渲染引擎，ASS 特效完整 |
| 超分 | 交给已装的 NijiLucid 扩展 | 无需开发，扩展自动接管原生 video 元素 |
| 搜索匹配 | 用户手动输入关键词 | 明确不做番名别名表/模糊匹配 |

## 2. 一次「下载一集」的完整流程

1. 用户在某部番的详情页点「找资源」，或直接打开搜索面板。
2. 前端请求 `GET /api/offline/search?q=<关键词>`。
3. 后端按镜像顺序请求蜜柑搜索 RSS，解析成结构化条目（字幕组/分辨率/编码/位深/字幕/大小/时间/合集），记住本次可用的主机。
4. 用户挑一条种子点「下载」→ 前端提交 `POST /api/offline/download`（番剧 id、集数键、种子直链、标题）。
5. 后端取回 .torrent 本体（校验 bencode 头），转交 qB：
   `POST /api/v2/torrents/add`，带上手账专用分类和标签，保存路径指向待整理区。
6. 前端轮询 `GET /api/offline/state`，格子上显示百分比。
7. qB 报告完成后，后端定位落地文件，用 ffprobe 探测容器与编码。
8. remux：`-c copy -tag:v hvc1 -movflags +faststart`；同时抽出内封字幕存成 `.ass`。
9. 归档：移到媒体库目录，重命名为 `第 01 集.mp4`，原始文件按规则保留或删除。
10. 状态改为「可播放」。用户在格子上点播放 → 网页内直接播。

## 3. 数据与目录

### 媒体库目录（可配置，默认在项目外）

```
D:\动漫\离线视频\
  └─ 全金属狂潮\
       ├─ 第 01 集.mp4          ← remux 后的成品，网页播的就是它
       ├─ 第 01 集.ass          ← 抽出来的字幕，jassub 用
       ├─ 第 02 集.mp4
       └─ source\
            ├─ 原种子文件名.mkv   ← 仅转码情形保留；remux 成功即删除
            └─ .torrent          ← 留档，方便日后重下
```

**为什么必须在项目外**：项目目录会被同步脚本推到 GitHub，几十 GB 视频一旦进去，历史记录清不掉。

### 新增数据库表 `local_media`

| 字段 | 用途 |
|---|---|
| `anime_id` / `episode_key` | 定位是哪一集 |
| `torrent_hash` / `torrent_name` | 对应 qB 里的任务 |
| `group_name` / `resolution` / `codec` | 从标题拆出来的来源信息 |
| `status` | `queued` / `downloading` / `processing` / `ready` / `failed` / `missing` |
| `file_path` / `file_size` / `duration_ms` | 成品文件信息 |
| `resume_ms` | 播放进度，用于续播 |
| `source_title` | 原始种子标题，换源时对照 |
| `created_at` / `updated_at` | 排序与清理 |

一集可能有多条历史记录（换源），以 `status='ready'` 的那条为准。

## 4. 一集的状态机

| 状态 | 含义 | 格子上怎么显示 |
|---|---|---|
| `none` | 没有本地文件 | 普通底色 |
| `queued` | 已提交 qB，还没开始 | 小圆点 + 0% |
| `downloading` | 下载中 | 进度百分比 |
| `processing` | 下完了，正在 remux/归档 | 转圈 |
| `ready` | 可以播 | 实心标记 + 播放按钮 |
| `failed` | 失败（无种/文件缺失/转换失败） | 红色角标，点开看原因 |
| `missing` | 记录还在，文件被手动删了 | 灰色虚线 |

`downloading` 到 100% 后还有校验和做种阶段，**只要 qB 报告 100% 就算「已下载」**，不再等做种。

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/offline/search?q=&limit=` | 蜜柑搜索 |
| POST | `/api/offline/download` | 提交下载 |
| GET | `/api/offline/state?anime_id=` | 该番每集状态 |
| POST | `/api/offline/delete` | 删除（三档模式） |
| GET | `/api/offline/stream/<media_id>` | 视频流，支持 Range 头 |
| GET | `/api/offline/subtitle/<media_id>` | 返回 .ass |
| GET/POST | `/api/offline/settings` | 媒体库目录、自动追番、字幕组偏好 |
| POST | `/api/offline/migrate` | 迁移媒体库 |
| POST | `/api/offline/retry` | 重试失败任务 |

`stream` 必须支持 HTTP Range，否则 `<video>` 拖进度条会失效。所有写接口要登记进 `write_exempt_paths` / `UNLOCKED_WRITES`。

## 7. 失败与边界

| 情况 | 处理 |
|---|---|
| 下载 30 分钟没有速度 | 标记可疑，提示「这个种子可能没人做种，建议换一个」 |
| 提交失败 | 自动重试 3 次，间隔递增，仍失败则标 `failed` 并记录原因 |
| 文件下完但找不到 | 标 `failed`，提示检查 qB 的保存路径设置 |
| remux 失败 | 保留原文件，标 `failed`，允许「用播放器打开」看原文件 |
| 单集超过 10 GB | 下载前提醒一次 |
| 磁盘剩余 < 20 GB | 顶部提示，不阻止 |
| 删除 | 三档：只删文件 / 删文件+任务 / 连记录一起删。默认只删文件，文件进回收站 |
| 迁移媒体库 | 逐集复制并校验，全部成功才删源；失败停止且不动旧文件；迁移中禁止播放 |

## 8. 明确不做的

- ❌ 浏览器扩展嗅探 m3u8、规则自动解析扒站 —— 蜜柑已经覆盖，不做第二套
- ❌ m3u8 / HLS 播放 —— 既多一层切片，又会让超分扩展失效
- ❌ 转码队列常态化 —— 只留作 AV1/损坏文件的后备
- ❌ 离线预渲染超分 —— 收益为零，实时超分已在
- ❌ 番名别名表 / 模糊匹配 —— 用户自己搜
- ❌ 手机端访问 —— 服务仍绑 `127.0.0.1`
- ❌ 自建 BT 引擎 —— 用 qB
