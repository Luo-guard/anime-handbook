# AnimeSchedule 已播集数来源

设置 → 收藏夹、设置 → 周表各有独立的「已播集数来源」：

- BGM / Bangumi：保持现有逐集日期与放送时刻的计算方式。
- AS / AnimeSchedule：使用 AS 原声和字幕放送事件中的较早时间，不计配音事件。不修改个人已看集数、收藏状态或周表放送时间。

默认仍为 BGM，选择后点击「保存设置」。收藏夹选项用于其番剧详情的已播集数、下一集时间；周表选项用于卡片进度。两项互不影响，也独立于有 C / Kazumi 周表来源。

## 配置与缓存

后台读取 `ANIMESCHEDULE_TOKEN` 环境变量，或数据目录下的 `animeschedule/token.txt`。本机数据目录通常为项目 `data/`；线上版使用独立数据目录下的 `cache/animeschedule/token.txt`。令牌不进入数据库设置、浏览器或仓库。本机已使用用户提供的令牌配置。

初次选择 AS 时，后台加载编号关联及近期日程；页面先显示加载状态，随后由已有的进度刷新更新，无需反复开关设置。相关缓存均保存在 `animeschedule/` 内。网络工作只有一个后台队列，单次请求超时 15 秒、请求间隔至少 0.7 秒、失败退避 10 分钟；翻页和 HTTP 读取本身不等待远程接口。日程最多每 15 分钟刷新，编号查询缓存一天，对照表缓存一周。

## 关联与显示规则

通过 Bangumi ID 查询社区跨站表，再按 MAL、AniList 或 AniDB 编号请求 AS。至少两个编号一致、所有共有编号没有矛盾且只对应一个 AS 条目时才接受。不会以名称相似度强行绑定；拆分篇章、多候选和仅一个编号的情况保持未匹配。

从上周、本周及下周 AS 日程读取明确的集号与日期，合并同一集的原声／字幕重复事件，使用已到达的最大集号。不按「下集减一」或每周递增来猜进度。总集数优先用 AS，缺失时沿用收藏条目总集数；如果总数小于 AS 已播集号，则仅显示「已播 N 集」。

AS 暂无可靠对应或近期没有可用日程时显示「暂无 AS 进度」，不会回退为 BGM 或每周估算。较早已完结、长期停播或未收录作品不保证有可用 AS 进度。断网保留已有日程缓存，超过 6 小时未更新时在进度提示中注明缓存状态。

AS 数据是放送计划，不是视频资源探测，也不保证中国大陆各平台、字幕组或先行资源与其同步。

## 来源

- [AnimeSchedule](https://animeschedule.net) / [API 文档](https://animeschedule.net/api/v3/documentation)：已播事件和后续日程。
- [BangumiExtLinker](https://github.com/Rhilip/BangumiExtLinker)，CC BY 4.0：跨站编号对照。对照表本身可能存在数据错误，后续可在其上游反馈，未把社区数据当作绝对可靠的官方绑定。

该实现用于共用网页与后台，未修改原生安卓版 APK。

## 第三套独立周表

周表顶部的来源选择与「设置 → 周表 → 周表来源」均可选择 AS / AnimeSchedule，和長門番堂（有 C）、Kazumi / Bangumi 并列。原有的显示来源切换开关仍控制顶部入口；即使隐藏入口，也能在设置里选择 AS。

AS 使用实际周次而非重复展示季度模板：显示周次和日期范围，左右箭头切换前后周，七个星期页签按北京时间凌晨 4 点换日。搜索只作用于当前周，不混入有 C 或 BGM 的作品列表；每次请求保留原有取消／版本检查，快速切换不会显示上一个来源的结果。

核对前后相邻周的原声、字幕事件，同一集只取最早可用的放送，避免本周电视重复放送上周已上线的同一集。整批发布在同日合为一张卡；确有多日不同集数更新的作品可以出现在不同星期。延期事件不算已播，仅延期安排的卡片显示「放送延期」。

已确认编号的条目补上中文名、收藏状态、可用的 BGM 评分及收藏操作。未确认编号的条目仍显示 AS 原名、时间、封面和 AS 详情链接，允许浏览，但不凭同名直接绑定收藏。

**周表来源和已播集数来源保持独立。**选择 AS 周表不会自动修改两处已播集数设置；想让卡片同时使用 AS 已播集数，应把「周表 → 已播集数来源」也设为 AS。AS 卡片的评分依旧来自已关联的 BGM 资料，不混用 AS 用户评分。

日程及条目资料由后台补充，首次加载时会先显示已有卡片；封面按需下载并缓存。AS 令牌仍仅由后台持有，来源链接保留在周表页脚和详情里。
